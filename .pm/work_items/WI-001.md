# WI-001 — Convert the master plan into an executable task roadmap

## Work Item ID
WI-001

## Goal
Turn `documentation/PLAN.md` and `deep-research-report.md` into a clean, executable project roadmap and the first implementation work item. This work item does not build the product.

## Source-Plan References
- `documentation/PLAN.md`
- `deep-research-report.md`

## Context
The repository is currently a research and planning repo. The immediate need is PM scaffolding, source-plan summary, backlog, decision log, and a small first implementation work item that OpenCode can execute later.

## Tasks
This work item contains exactly three tasks.

### WI-001-TASK-1
- Objective: Analyze the source plan documents and produce a technical planning summary.
- Deliverable: `.pm/PLAN_SUMMARY.md`
- Acceptance criteria:
  - `.pm/PLAN_SUMMARY.md` exists.
  - It clearly reflects both source documents.
  - It identifies the recommended technical direction.
  - It lists unresolved decisions and risks.
  - It does not invent implementation details not grounded in the source documents.
- Out of scope:
  - Writing production code.
  - Installing dependencies.
  - Modifying Blender add-on code.

### WI-001-TASK-2
- Objective: Create a source-plan-aligned backlog and architecture decision log.
- Deliverables: `.pm/BACKLOG.md`, `.pm/DECISIONS.md`, `.pm/PROJECT_BRIEF.md`
- Acceptance criteria:
  - `.pm/BACKLOG.md` exists and is staged into clear milestones.
  - `.pm/DECISIONS.md` exists and contains at least one justified ADR or a note explaining why no ADR can be made yet.
  - `.pm/PROJECT_BRIEF.md` exists and accurately summarizes the project.
  - The backlog reflects the source documents instead of generic assumptions.
- Out of scope:
  - Writing production code.
  - Creating Blender files.
  - Installing ML libraries.

### WI-001-TASK-3
- Objective: Create the first implementation work item based on the aligned roadmap.
- Deliverable: `.pm/work_items/WI-002.md`
- Acceptance criteria:
  - `.pm/work_items/WI-002.md` exists.
  - WI-002 contains exactly three tasks.
  - Each task has a concrete deliverable.
  - Each task has acceptance criteria.
  - Each task has out-of-scope boundaries.
  - WI-002 is directly aligned with the master plan.
- Out of scope:
  - Executing WI-002.
  - Installing large dependencies.
  - Building the full Blender integration.

## Expected Combined Deliverable
Planning artifacts that summarize the master plan, define staged backlog and decisions, and create a first implementation work item small enough to delegate safely.

## Acceptance Criteria
- `.pm/PLAN_SUMMARY.md` exists.
- `.pm/BACKLOG.md` exists.
- `.pm/DECISIONS.md` exists.
- `.pm/PROJECT_BRIEF.md` exists.
- `.pm/work_items/WI-002.md` exists.
- WI-002 contains exactly three implementation tasks.
- All outputs are aligned with `documentation/PLAN.md` and `deep-research-report.md`.
- No production code is added unless unavoidable.
- No large dependencies are installed.

## Risks
- Existing repo notes still mention a LoRATv2/C++ direction, while the current plan documents recommend MMPose/RTMPose out-of-process for v1.
- OpenCode may be unavailable or unable to reach its configured local model backend.
- Planning artifacts may drift into implementation scope if task boundaries are not enforced.

## Out of Scope
- Product implementation.
- Dependency installation.
- Model training or inference.
- Git commits.

## Task WI-002-1: MMPose Environment Validation

### Deliverable

A `tests/validate_mmpose.py` script that:
- Creates a minimal virtual environment with MMPose and RTMPose dependencies listed in `requirements.txt`
- Runs RTMPose-m inference on a sample video frame with known pose (e.g., test_frames/sample.mp4 or a generated synthetic frame)
- Outputs keypoints to stdout as JSON and saves to `tests/output/validated_poses.json`
- Prints a pass/fail summary (non-empty keypoints list = pass)

### Acceptance Criteria

- `pip install -r requirements.txt` completes without errors on a Python 3.11+ system
- `python tests/validate_mmpose.py` produces at least one person's keypoints with ≥ 2 detected persons in a sample image with visible human figures
- All 17 COCO body joints have coordinates for each detected person
- Inference completes in under 10 seconds on standard hardware
- Script exits with code 0 on success, non-zero on failure

### Out of Scope

- GPU/CUDA hardware setup (run CPU-only for initial validation)
- Testing on multiple video inputs
- Benchmarking latency or throughput
- Testing on custom character rigs

## Task WI-002-2: External MMPose Worker with CLI Entrypoint

### Deliverable

A standalone Python module at `mmpose_worker/` containing:
- `mmpose_worker/run.py` — Entry point CLI that accepts:
  - `--input` path to video or image
  - `--output` path to write JSON cache
  - `--model` choose RTMPose-m or RTMO (default: RTMPose-m per ADR-3)
  - `--device` cpu or cuda (default: cpu)
  - `--topk` number of persons to track (default: 5)
- `mmpose_worker/inferencer.py` — Inference logic module (separated from CLI for reusability)
- `mmpose_worker/__init__.py` — Package marker and version (`__version__ = "0.1.0"`)
- `mmpose_worker/config.py` — Default configuration with path to RTMPose-m checkpoint

### Acceptance Criteria

- `python -m mmpose_worker.run --input <path> --output <path>` runs end-to-end without errors
- Output JSON file contains a valid array of frames, each with person detections
- JSON files are created at the specified output path (not stdout)
- Worker can be imported and used programmatically as `from mmpose_worker.inferencer import detect_poses`
- Worker handles missing input file gracefully with a clear error message
- Worker prints progress (frame count, persons per frame) to stderr during execution

### Out of Scope

- GPU inference (CPU-only for v1 worker validation)
- Streaming/real-time video processing
- Frame caching, resuming, or parallel processing
- Model downloading (assume checkpoints are present)
- Multi-person ID persistence logic (just output per-frame detections)

## Task WI-002-3: Tracking Result JSON Schema Specification

### Deliverable

A JSON schema file at `mmpose_worker/schemas/tracking_result.json` and a Python validation helper at `mmpose_worker/validate_schema.py`:
- Schema defines the output structure: frames array, each with frame_index, width, height, persons array, each with track_id (nullable for first frame where persistent ID is not yet established), keypoints array of 17 COCO joints (each with x, y, score), and bbox (x, y, width, height)
- Validation script loads any JSON output and returns success/failure with field-level error messages
- Schema file includes inline comments (as JSONC with `--schema-description` field) documenting what each field means

### Acceptance Criteria

- Schema file is valid JSON and can be parsed by any JSON schema validator
- Running `python mmpose_worker/validate_schema.py --schema mmpose_worker/schemas/tracking_result.json --input <any_valid_output.json>` returns success
- Schema enforces: exactly 17 keypoints per person, numeric x/y coordinates in 0..1 range, score in 0..1 range
- Schema is documented enough that a developer unfamiliar with MMPose can understand the output format
- Validation script includes a built-in test case (embedded valid JSON with one person, 17 keypoints) that passes

### Out of Scope

- Full JSON Schema draft compliance/validator enforcement
- Schema versioning or migration tools
- Cross-referencing with Blender addon schema (separate work item)
- Schema validation under performance pressure

## Summary

WI-002 provides the foundation for all downstream Blender integration work:

1. **Environment validation** proves MMPose runs correctly on a clean system

These three tasks must complete before any Blender-side work begins (Phase M3).
